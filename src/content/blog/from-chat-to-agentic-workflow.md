## 范式转移：从 Prompt 到 Workflow

过去，我们衡量 AI 使用水平的标准往往是：“谁的 Prompt 写得更好”、“谁能诱导模型给出更高质量的单次回复”。

但随着长上下文（Long-Context）、结构化输出（Structured Outputs）以及工具调用（Tool Use / Function Calling）的成熟，整个 AI 辅助开发的重心正在发生根本性的位移：

**从“对话型交互”全面转向“任务编排型交互”（Agentic Workflow）。**

```
传统模式：人类输入 Prompt ──> LLM 吐出整块代码 ──> 人类手动复制粘贴测试
Agent 模式：人类下达目标 ──> Agent 自主阅读代码 ──> 拆解步骤 ──> 执行修改 ──> 运行测试并自愈
```

## 个人开发者在 Agent 时代的优势

在大厂组织中，工具的引入伴随着层层安全审批和合规流程；而作为独立开发者或小团队，我们可以以最快的速度把前沿工具焊接入自己的开发管线：

1. **认知负荷的卸载**：把重复性高、容错要求严密的枯燥活（写测试、做类型定义、配置 CI/CD、编写迁移脚本）外包给 Agent 执行；
2. **多线程并发**：人类负责架构设计与目标拆解，Agent 在后台进行代码搜索、数据提取与原型验证；
3. **单兵作战能力指数级放大**：以前做一个产品需要前端、后端、设计、运维多角色配合，现在一个全栈开发者借助成熟的 Agent 生态即可覆盖完整产品交付生命周期。

## 保持克制：不要陷入“Agent 玩具陷阱”

尽管 Agent 概念火热，但在实际落地中，我始终保持着一份审慎：

- **确定性优先于灵活性**：如果一个 shell 脚本或 5 行代码能解决的问题，坚决不让非确定性的 LLM 去做；
- **小闭环优于大幻觉**：与其期待一个通用 Agent 一键完成整个 App，不如让专门的 Agent 专注解决单一明确的子任务；
- **透明度与可干预性**：每一个写入操作都应该清晰可见，把最终决定权牢牢握在开发者手中。
